## Changes verified for RC2

### LinkedIn duplicate prevention

- A valid empty LinkedIn 2xx create-post response without `Content-Type` is accepted.
- `x-restli-id` is read before classifying the write as failed.
- `linkedin_write_started` is persisted before the create POST.
- `linkedin_post_id` and `linkedin_write_completed` are persisted before target completion.
- An ambiguous result after the write barrier is non-retryable and marked `outcome_unknown`.
- Resuming the package after an ambiguous LinkedIn result cannot make a second create POST.
- A completed progress record is recovered without any new LinkedIn create request.

### Threads UNKNOWN

- Literal `UNKNOWN` is converted to a descriptive non-retryable error.
- The package pauses instead of performing three blind attempts.

### Media / video

- Real video candidates outrank poster/thumbnail/`og:image` candidates from the same source.
- If selected media returns HTTP 404, source discovery is repeated once.
- Refreshed same-source video is preferred when available.
- Media discovery and download failures now produce safe application-log diagnostics.
