## Incident basis

Live RC6 packages #165, #166 and #167 stopped on their first Facebook target with a generic `донатний коментар` unknown-outcome error. The remaining independent Threads, LinkedIn and Telegram targets were therefore not attempted. A manual retry of #165 was then blocked by the durable Facebook write marker.

The logs do not prove whether the corresponding Facebook root posts are publicly visible. RC7 therefore never treats those root posts as safe to recreate blindly.

## RC7 changes

- explicit Facebook/Meta `PublishError` details are preserved instead of being replaced with one generic message;
- a definite API rejection clears only the current phase's `started` marker so a corrected request can be retried safely;
- an ambiguous Facebook write retains its durable phase marker, preventing blind duplicate Facebook writes;
- Facebook ambiguity is contained to that Facebook target so independent Threads, LinkedIn and Telegram targets in the package may continue;
- existing unresolved Facebook phase markers no longer abort the remaining platforms;
- legacy queued payloads containing the old donation footer are normalized and routed through the current comment-aware publisher instead of bypassing it;
- regression tests cover explicit comment API rejection, ambiguous comment write, unresolved comment marker, explicit root-post rejection, successful root+comment and legacy footer normalization.
