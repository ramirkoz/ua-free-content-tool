# UA FREE Content Tool v1.2.0 — Scope

Status: development planning and implementation
Baseline: stable public release v1.1.4
Development branch: `feature/v1.2.0-editorial-memory-media`

## Product goal

Remove two avoidable operator burdens:

1. make the local editorial memory understandable without technical knowledge;
2. replace the manual browser → local file → Google Drive → copied link → verification workflow with an automatic media pipeline inside the editor.

The v1.1.4 release tag and release assets remain immutable.

## 1. Editorial memory UI

Issue: #10

Rename `Локальне навчання` to `Редакційна пам’ять`.

Display this explanation directly in Settings:

> Програма не перенавчає Ollama. Вона зберігає ваші схвалені тексти й додає найбільш схожі з них до наступних запитів.

Replace technical labels with clear operator language:

- no modification of Ollama model files;
- existing editorial examples remain valid;
- Ukrainian and English memory stay separated;
- v1.1.4 Data must open without losing learning records.

## 2. Automatic media pipeline

Issue: #11

### Target operator workflow

When media exists in collected sources:

1. open a news block in the editor;
2. see media candidates from every article in the block;
3. select one image or video;
4. press `Використати вибране`;
5. the application downloads, validates, uploads to Google Drive, verifies, attaches, and reports `Медіа готове ✓`.

When source media is absent:

- `Додати з комп’ютера`;
- `Додати за посиланням`.

Both actions use the same validation, Drive upload, verification, and attachment pipeline.

### Media discovery

Candidates may be extracted from:

- RSS/Atom media elements and enclosures;
- images embedded in RSS content;
- Open Graph image/video metadata;
- Twitter Card metadata;
- safe and unambiguous schema.org image/video metadata;
- Telegram public-preview photos, video posters, and video URLs;
- the main article HTML.

Candidates are deduplicated and labelled by source.

### Media editor

Replace the raw Google Drive URL field with `Медіа для публікації`:

- thumbnail gallery;
- source label;
- image/video type;
- known size and dimensions;
- select one candidate;
- use selected;
- add from computer;
- add by URL;
- remove media;
- visible progress and error state;
- final attached-media preview and Drive verification state.

The first v1.2.0 implementation supports one selected media file per publication. Carousel support remains out of scope.

### Google Drive

The application must:

- find or create a dedicated `UA FREE Content Tool Media` folder;
- store its folder ID in encrypted configuration;
- upload selected remote or local media itself;
- receive and store the Drive file ID;
- run the existing authenticated inspection;
- keep the existing temporary public permission flow for Threads;
- delete the Drive file only after all selected platforms succeed;
- never automatically delete a third-party Drive file that was not uploaded by the application.

### Remote URL behavior

A pasted URL may be:

- a direct image/video URL, which is downloaded and validated;
- an HTML page URL, which is scanned for media candidates and returns a choice dialog.

Only HTTP/HTTPS is accepted. Existing SSRF, DNS, redirect, and public-IP protections remain mandatory.

### Storage and migration

Expected database schema: 9.

Add persistent media-candidate records linked to articles or groups. Preserve existing attached-media columns and existing queued publications.

Migration 8 → 9 must:

- make a durable pre-migration backup;
- preserve sources, queue, tokens, history, metrics, exclusions, and editorial memory;
- leave existing Drive attachments usable;
- fail closed without modifying the live database if validation fails.

### Runtime dependency

Pillow may be added as a pinned runtime dependency to display JPEG, PNG, and WebP thumbnails reliably in Tkinter.

Any dependency change requires the full signed-runtime, Windows CI, portable startup, Microsoft Defender, and ZIP-integrity release gates.

## Implementation order

1. Rename and explain Editorial Memory UI without changing its data logic.
2. Add media-candidate model and schema-9 migration.
3. Extract media from RSS, article metadata, and Telegram previews.
4. Add safe remote/local media validation.
5. Add Drive folder discovery/creation and upload.
6. Build thumbnail gallery and manual-add dialogs.
7. Connect selection to existing queue and publication media flow.
8. Test restart, replacement, failure rollback, partial retry, Threads permission, and final cleanup.
9. Run Windows CI and release-security gates.
10. Publish v1.2.0 only after manual acceptance on the working Data copy.

## Explicitly out of scope

- automatic media selection without operator confirmation;
- multiple media files or carousels;
- image editing or AI generation;
- browser automation;
- direct publishing of unverified remote hotlinks;
- changing the stable v1.1.4 release bytes.
