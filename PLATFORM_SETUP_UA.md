# Налаштування платформ R8 FIX28

## Meta App ID і App Secret

Facebook і Threads можуть працювати через один Meta-застосунок, але використовують різні access tokens. У FIX23 вкажіть Meta App ID і Meta App Secret, щоб програма могла обмінювати короткі токени на довготривалі. App Secret зберігається у тій самій зашифрованій конфігурації, що й токени, і не записується у журнали.

## Facebook

Використовується один Facebook User Access Token. Програма через `/me/accounts` завантажує доступні сторінки та їх Page Access Tokens. Програма зберігає й показує всі сторінки, які повертає токен, без ліміту у дві позиції.

Токен із Graph API Explorer зазвичай короткотривалий. Після введення App ID, App Secret і чинного User Access Token натисніть `Знайти сторінки`: FIX23 спочатку намагається отримати довготривалий токен, потім зберігає всі Page Access Tokens і показує строк дії. Прострочений token не обмінюється; спочатку потрібно створити новий.

## Threads

Потрібен Threads Access Token з дозволами:

```text
threads_basic
threads_content_publish
```

Для порівняння новини з актуальними Threads-дописами додатково потрібен:

```text
threads_keyword_search
```

Кнопка `Перевірити пошук трендів` звертається до актуального endpoint `graph.threads.net/keyword_search`, очікує не довше 12 секунд і завжди показує окреме вікно з результатом. Повторно визначати профіль для цієї перевірки не потрібно.

Після визначення профілю програма автоматично перевіряє доступ до пошуку трендів. Без цього дозволу публікація працює, але оцінка вибуховості позначається як часткова.

За наявності App Secret короткий Threads token обмінюється на довготривалий. Чинний довготривалий token програма намагається оновити до завершення строку. Уже прострочений token автоматично оновити неможливо, тому потрібно створити новий.

## LinkedIn

1. Відкрийте LinkedIn Developer Portal Token Generator.
2. Створіть токен із дозволами `openid`, `profile`, `w_member_social`.
3. Вставте токен у програму та натисніть «Перевірити токен».

Програма визначає особистий профіль автоматично. Для LinkedIn готується окремий коротший професійний текст.

## Telegram

Потрібні:

- Bot Token від `@BotFather`;
- username або ID каналу;
- бот має бути адміністратором каналу з правом публікувати повідомлення.

## Google Drive для медіа

### Один раз у Google Cloud

1. Закрийте банер `Start free` кнопкою `Dismiss`; Free Trial програмі не потрібен.
2. Створіть власний Google Cloud проєкт.
3. Увімкніть Google Drive API.
4. Налаштуйте OAuth consent screen для свого акаунта.
5. Створіть OAuth Client ID типу `Desktop app`.
6. Скопіюйте Client ID і, якщо показується, Client Secret у налаштування R8.
7. Натисніть «Підключити Drive» і дозвольте доступ у браузері.

Програма зберігає refresh token у DPAPI-конфігурації. Доступ потрібен, щоб завантажити ваш файл для платформ і після повного успіху безповоротно його видалити.

### Для кожної новини

1. Завантажте одне фото або одне відео у свою папку Google Drive.
2. Залиште папку й файл приватними. Ніякі дозволи вручну змінювати не потрібно.
3. Скопіюйте посилання на конкретний файл, вставте його у вкладці «Публікація» й натисніть «Перевірити медіа».

Перевірка підтверджує:

- файл є зображенням або відео;
- підключений Google-акаунт може його завантажити й безповоротно видалити;
- для Threads акаунт має право тимчасово відкрити доступ до конкретного файла.

Під час публікації в Threads програма сама створює тимчасовий доступ `anyone/reader`. Після помилки доступ закривається, а після повного успіху файл безповоротно видаляється. Загальний доступ до всієї папки не потрібен.

## Facebook без ліміту у дві сторінки

Після введення Facebook User Access Token натисніть «Знайти сторінки». Програма читає всі сторінки, доступні токену, включно з наступними сторінками API-пагінації. Всі вони автоматично стають окремими цілями у редакторі.

## Збереження токенів

Кнопка `ЗБЕРЕГТИ ЗМІНИ` постійно видима у верхній частині вкладки. Успішні перевірки Facebook, Threads, LinkedIn, Telegram і Google Drive також зберігають перевірені дані одразу.


## Автоматична перевірка всіх підключень

Після запуску програма автоматично перевіряє актуальність збережених підключень, а потім повторює перевірку кожні 6 годин. Результат показується у верхній частині розділу `Платформи й Google Drive`. Автоматична перевірка не відкриває модальних вікон і не блокує роботу; ручна кнопка показує окреме підсумкове повідомлення.

Стани розділені навмисно:

- `актуальний` — live API підтвердив токен і потрібний read-only доступ;
- `замінити токен` — платформа прямо повідомила, що токен недійсний, прострочений, відкликаний або створений без потрібного дозволу;
- `перевірити права` — токен працює, але бракує ролі або права, наприклад бот Telegram не є адміністратором каналу;
- `тимчасово не перевірено` — збій мережі, DNS або платформи; програма не радить перевипускати токен без доказу;
- `не налаштовано` — відповідне підключення відсутнє.

Для Telegram недостатньо лише правильного Bot Token: бот повинен бути адміністратором каналу й мати `can_post_messages`. Для LinkedIn програма читає фактичний текст помилки `/v2/userinfo`, включно з `status`, `serviceErrorCode` і `message`.


## Відновлення пропущених публікацій FIX23

Після заміни прострочених токенів відкрийте `Черга` і натисніть `Перепланувати пропущені / призупинені`. Програма збере призупинені пакети та прострочені pending-пакети, розставить їх у найближчі майбутні слоти за поточним інтервалом і не повторить targets, які вже мають статус `sent`.
